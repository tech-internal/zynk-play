What this system does

The XP Management module is a centralized reward engine for the Zynk Play platform. Every XP credit or debit flows through a single pipeline: validate event → apply rule → write ledger → update wallet. Direct database updates to balances are not supported.

User action → POST trigger-event → Rule engine → Ledger + wallet → Response

Engagement pillars

  • watch Streams, VOD, highlights
  • pay Purchases & subscriptions
  • win Matches, tournaments, challenges
  • share Social sharing
  • platform Login, profile, referrals

Quick start for integrators

  1. Obtain platform JWT for a user (see API authentication).
  2. Call POST /api/v1/xp/trigger-event with a registered event_code and unique idempotency_key.
  3. Read balance via GET /api/v1/xp/balance?user_id=....

Full PDF-style documentation: docs/XP_MANAGEMENT_INTEGRATION.md in the repository.

Data model

TablePurpose
xp_eventsRegistry of valid event codes (must exist before XP can be awarded)
xp_rulesPer-event rules: base XP, caps, cooldown, formula, expiry
user_xp_walletOne wallet per user: available, earned, redeemed, expired, tier
xp_transactionsImmutable ledger (credits, debits, expiry, reversals)

Rule resolution order

  1. Resolve active rule for event_code (respect valid_from / valid_until).
  2. Check idempotency key (duplicate returns original result with HTTP 200).
  3. Check lifetime cap, daily cap, cooldown.
  4. Compute XP (formula + tier multiplier).
  5. Atomic wallet update + confirmed transaction.

Platform JWT (required for all XP APIs)

All /api/v1/xp/* endpoints require Authorization: Bearer <access_token>. Tokens are issued by the entertainment platform auth API after OTP verification.

For sandbox testing, use mock OTP: any phone number with code 123456.
